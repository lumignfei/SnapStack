# 浮窗尺寸同步修复 · 2026-10-10

用户反馈：展开备注后顶部和底部裁切；收起备注后仍维持大窗口；删空截图后残留展开尺寸。

修复让队列视图与外层窗口从同一状态获得尺寸，移除延迟 GeometryReader 回调驱动的尺寸变更；关闭宿主自动尺寸约束与 autoresizing，避免与手动 NSPanel 布局竞争。内容靠顶部排列，状态文字预留两行。尺寸为有图 540×244、备注展开 540×403、空队列 540×226 pt。原有弹出/收起和长条形变动效保留。

已用正式 UI 源码和独立测试截图，在原生窗口实际点击验证：紧凑 → 展开 → 收起 → 再展开 → 删除最后一张 → 关闭并重新打开。每一步窗口与内容同步，标题、缩略图和输入框没有裁切，空队列没有残留展开高度。自动化 AX 点击在此测试环境会引发窗口外点击关闭；改用基于最新截图的坐标点击后连续流程通过。

测试应用已关闭。更新前原有一张截图备份于 `.build/before-popover-fix/queue-backup/`；旧源文件备份于 `.build/before-popover-fix/`。

正式 release 构建及签名校验通过。所有 stablePopover 调用必须提供明确尺寸；更多菜单固定为 220×199 pt，避免关闭宿主自动尺寸后 fittingSize 返回零。已刷新现有辅助功能和屏幕录制授权并重启正式版，实际检查更多菜单和空队列浮窗均完整显示。
